# Исследование 04 — вынос текстов из кода в ресурсы и механизм языков

> **Создан:** 2026-10-16 · **Родитель:** researches/03_tribit_app_pains.md (разделы 6–7) · **Статус:** разведка · **Вовне:** —
>
> Задание владельца: «выносим локали в файл из кода», и дополнение: «тексты приходят с их сервера, часть
> китайского зашита в код — будем перехватывать их тексты и ставить НАШИ АДЕКВАТНЫЕ тексты». Только чтение кода,
> ни одного запроса к серверу Tribit. Пути кода — от `decompiled/jadx-base/sources/`, smali и ресурсы — от
> `work/base/`. Все числа посчитаны скриптами (раздел 2, внизу — команды).

## Коротко

- Узкое место найдено, и оно одно: **`ResourceUtils.getStringFormServer(int)`**. Через него идут оба
  `ResourceUtils.getString` — 5394 вызова в коде, 647 разных ключей. Ключ сервера — это **имя строки из
  `values/strings.xml`**. Значит, перевод в `values-ru` ложится на те же имена, и придумывать ключи не нужно.
- Если подменить этот один метод и поставить настоящий Locale, большая часть интерфейса начнёт читать наши
  файлы ресурсов. Отдельные скрипты понадобятся для того, что зашито в разметку (259 текстов, 106 разных) и
  в код (264 текста в `setText`/Toast/диалогах, 125 разных, 169 из них китайские).
- Раздел 6 исследования 03 надо уточнить: ресурсами это **чинится**, причём дешевле, чем писать своё
  приложение. Механизм сервера сделан как надстройка над `getString`, а не вместо него.

## 1. Как текст попадает на экран сейчас

**Загрузка.** Текст с сервера загружается в двух местах, код у них одинаковый:
- при старте, на экране входа: `FirstNewActivity:153–160` (и `FirstActivity:157`) →
  `ViewModelFirst.getStringResources:64–112`. Запрос уходит, только если `NetworkUtils.isConnected()`;
- при выборе языка: `SettingsNewActivity:486–506` (и `SettingsActivity:504`) →
  `ViewModelSettings.getStringResources:135–178`.

Запрос — `new ProductString("Tribit", lang)` → `api-app/api/lang/getLangInfoBySchemaOrLangKey`
(`http/model/ProductString.java:44`). Ответ — карта `{lang: {key: text}}`.

**Хранение.** Каждая пара пишется как есть: `SPUtils.getInstance().put(key, value)`
(`ViewModelSettings:155–157`, `ViewModelFirst:95–98`). `SPUtils` хранит данные не в SharedPreferences, а в
MMKV с id `"spUtils"` (`tool/utils/SPUtils.java:31,57`). Это то же хранилище, где лежат все настройки
приложения (`app_language`, `api_lang`, токены). Таблицу `LangBean`, упомянутую в 03, заполняет только
`UpdateUtils$getStringResources$1:41`, а этот класс в smali нигде не создаётся (поиск
`UpdateUtils$getStringResources$1;-><init>` пуст), то есть это мёртвый код. После записи
`UpdateUtils.replaceString:599–617` правит две строки: `###` → `%1$s` в `tribit_login_with` и
`******@***.com` → `%1$s` в `not_find_check`. Затем экран настроек перезапускает приложение
(`SettingsNewActivity:287–293`).

**Показ — обёртка над `getString`, а не свой TextView и не своя фабрика разметки.** Своих фабрик разметки
и подмены `Resources` нет: поиск `setFactory2`, `LayoutInflater.Factory`, `extends Resources`, ViewPump не
нашёл ничего в `com.thousandshores`. Весь перехват сидит в `tool/utils/ResourceUtils.java`:

```
ResourceUtils.java:36-37  String s = getStringFormServer(i);
                          return TextUtils.isEmpty(s) ? Utils.getApp().getResources().getString(i) : s;
ResourceUtils.java:44,46  String key = getResources().getResourceName(i).split("/")[1];
                          return SPUtils.getInstance().getString(key, "");
```

Порядок такой: текст сервера из MMKV по имени ресурса, если его нет — `values/strings.xml`, причём через
ресурсы **Application** с системным Locale. Вариант с аргументами (`:54–64`) работает так же и
форматирует текст через `String.format`. В smali: `smali_classes4/com/thousandshores/tool/utils/ResourceUtils.smali`
— `getString(I)` в строке 167, `getString(I[Object)` в строке 214, обе вызывают
`getStringFormServer(I)` из строки **319**. Есть ещё `getStringFormServer(String)` в строке 371 с
произвольным ключом: 7 вызовов, это заголовки и списки изменений прошивок (`DeviceUpdateNewDialog:142–178`,
`UpgradeHistoryAdapter:31`).

Отсюда главное следствие: на экране получаются **три источника** текста.

| Откуда текст | Как попадает | Объём (скрипты) | Сервер действует? |
|---|---|---:|---|
| `ResourceUtils.getString(R.string.X)` | через MMKV, потом `values/` | 5394 вызова, 647 ключей | да |
| `@string/X` в разметке, `context.getString(R.string.X)` | Android напрямую | 214 ключей в разметке (90 только там), 77 вызовов в коде (`PermissionInterceptor` — 18) | **нет**, всегда английский |
| Литералы в разметке и коде | зашиты | 259 + 264 текста (раздел 2) | нет |

Экраны сами переписывают свои тексты через `ResourceUtils`: метод `initStrings()` есть в 126 классах
(например, `SettingsNewActivity:311–319`). Поэтому многие китайские заглушки в разметке пользователь не
видит. Например, `activity_device_help_new.xml` на самом деле перезаписывается в `DeviceHelpNewActivity:139–236`.
Здесь 03 нужно поправить: «экран целиком по-китайски» — это о разметке, а не о том, что на экране.

**Если сервер недоступен.**
- Первый запуск без сети: запрос не уходит, сразу `showAgree()` (`FirstNewActivity:161–162`). Пользователь
  видит английский из `values/` плюс литералы.
- Сеть есть, но запрос упал: `onHttpFail` возвращает 1 (`ViewModelFirst:111`), дальше то же самое.
- Сервер ответил с `datas == null`: результат 2 и Toast «getStringResources …», а `FirstNewActivity:182`
  реагирует только на 1. Соглашение не показывается — возможно зависание на первом экране. Вывод сделан
  по коду, на устройстве не проверен.
- Один раз скачанный язык остаётся в MMKV навсегда и без сети. Срока годности нет: `user_login_time<lang>`
  только записывается и нигде не читается.
- Смена языка без сети: подпись языка меняется, тексты остаются прежними, перезапуска нет
  (`ViewModelSettings:174–176`).
- **Смешение языков.** Старые ключи при смене языка не удаляются. Если в новом языке на сервере нет
  какой-то строки, на экране остаётся строка прежнего языка.

**Ещё две находки.**
- `TribitApp.onConfigurationChanged` (`TribitApp:373`, smali `TribitApp.smali:703`) при **любом** изменении
  конфигурации записывает в `app_language` и `api_lang` системный язык. Ручной выбор пользователя
  затирается, хотя тексты не перезагружаются.
- `LanguageUtils.applyLanguage` читает `KEY_LOCALE`, которого никто не пишет (`LanguageUtils:22`). Настоящий
  Locale не ставится нигде.

## 3. Дизайн патча: перехват и наши тексты из файлов ресурсов

Принцип: **наш текст из `values-xx` важнее текста сервера. Текст сервера показывается только там, где
нашего ещё нет. Английский `values/` — последний запасной вариант.** Все патчи — в `patches/apply.py`, на
каждый якорь `FAIL`, как в патчах 1–7.

**Патч 8а — перехват в узком месте.** Тело `ResourceUtils.getStringFormServer(I)`
(`ResourceUtils.smali:319`) заменяется вызовом нового класса `Lkrinik/Strings;->server(I)Ljava/lang/String;`.
Класс небольшой, пишется на smali руками и кладётся в `smali_classes5/krinik/`. Логика:
1. Берём `key = getResourceName(id)` — так делает и исходный код.
2. Если `key` есть в нашем списке переведённых для текущего языка, возвращаем
   `res().getString(id)` — **наш текст**.
3. Иначе возвращаем `SPUtils.getString(key, "")` — как сейчас: текст сервера или пусто, и тогда вызывающий
   берёт английский из `values/`.

Как узнать, переведён ли ключ: генератор кладёт в `values-xx/krinik_meta.xml` массив
`<string-array name="krinik_overridden">` с именами ключей из `values-xx/strings.xml`, а в `values/` —
пустой массив. Читаем его один раз в `HashSet`. Это детерминированно и без сравнения строк.
`res()` — это `Resources` из `createConfigurationContext` с Locale по `app_language`, в кеше пересоздаётся
при смене языка. Так `getString(I)` и `getString(I, Object[])` остаются нетронутыми: непустой ответ они
отдают как есть или форматируют. Обёрточные методы не трогаем — одна замена тела метода покрывает **5394
вызова и 647 ключей**. Метод `getStringFormServer(String)` (371) подменяем так же, как `server(String)`, с
ключом из данных: это 7 вызовов, тексты прошивок.

**Патч 8б — настоящий Locale.**
- В `BaseActivity.attachBaseContext` (его добавляет патч 3) к тому же `Configuration` добавить
  `setLocale(map(app_language))`, где `tu→tr`, `zh→zh-CN`. Тогда `@string` в разметке (214 ключей, 90
  только там) и 77 прямых `context.getString` Android переведёт сам.
- Этим покрыты 140 из 146 своих экранов. Шесть не наследуют `BaseActivity`: `FirstActivity`,
  `FirstNewActivity`, `AmbientSoundActivity`, `HistoryDetailActivity`, `DialogManager$DialogDelegateActivity`,
  `UtilsTransActivity` — им нужен такой же метод отдельно, или оставить как есть.
- Обязательно: `TribitApp.onConfigurationChanged` (`TribitApp.smali:703`) не должен затирать
  `app_language`, если он уже задан. Иначе язык будет сбрасываться при повороте экрана.

**Патч 8в — литералы разметки → `@string`.** Скрипт `patches/externalize_layouts.py`:
- Проходит `res/layout*/*.xml` в отсортированном порядке. Каждое значение `text|hint|contentDescription`
  без `@`/`?`, в котором есть хотя бы две буквы, заменяет на `@string/kl_<sha1(текст)[:10]>`. Одинаковый
  текст — один ключ: 259 мест → 106 ключей. 109 чисел и знаков не трогаем.
- Записи пишет в `values/strings.xml` одним блоком между маркерами, в порядке ключей.
- Значение в `values/` — **наш английский** из таблицы `patches/strings/layout_en.tsv` (оригинал → English),
  а не китайский оригинал. Литерал, которого нет в таблице, даёт `FAIL`: новая версия Tribit принесла
  новый текст — громко.
- Экранирует `'`, `"`, `@`, `?` по правилам aapt2. Повторный прогон на уже обработанном дереве тоже `FAIL`,
  как `add_method`.

**Патч 8г — литералы кода.** Скрипт `patches/externalize_code.py` с белым списком
`patches/strings/code.tsv` (класс, метод, литерал, ключ). Список составляется один раз из 264 найденных
литералов и проверяется глазами. Для каждой строки:
- `const-string vX, "默认"` в указанном методе должен найтись ровно один раз, иначе `FAIL`.
- Он заменяется на `const-string vX, "kt_…"` + `invoke-static/range {vX .. vX}, Lkrinik/Strings;->t(Ljava/lang/String;)Ljava/lang/String;`
  + `move-result-object vX`. Форма `/range` работает с любым номером регистра, новых регистров не нужно.
- `t(key)` возвращает `res().getString(getIdentifier(key,"string",pkg))`. В `values/` лежит наш английский,
  в `values-ru` — русский.
- Литералы, которые участвуют в логике (`equals`, ключи карт, имена пресетов EQ в `return`), в
  автоматический список **не включаются**: их нужно разбирать вручную по каждому месту.

**Патч 8д — китайские строки библиотек.** Переписать значения `ps_*` (73), `brvah_*` (4), `logcat_*` (22)
и `eg_macbook` в `values/strings.xml` на английский, а в `values-ru` — на русский. Обычная правка ресурсов,
без кода.

**Что сломается и чего опасаться:**
1. **Переведённый текст используется как идентификатор.** `EqButton56Activity:347` сравнивает
   `eq.getCustomName()` с `ResourceUtils.getString(R.string.classical)`. Если имена пресетов EQ перевести,
   они перестанут совпадать с сохранёнными. Ключи пресетов EQ не переводить, пока не проверим на колонке
   владельца.
2. **Формат «#».** `DeviceHelpNewActivity:185–223` делит строку по `#` и берёт `get(1)` — 12 таких мест.
   Перевод без `#` уронит экран помощи. Генератор обязан сверять с английским число `#`, `%s`/`%1$s`/`%d`
   и `\n`, иначе `FAIL`.
3. Хаки `replaceString` (`###`, `******@***.com`) касаются только текста сервера. В наших файлах сразу
   пишем `%1$s`.
4. 85 веток `"zh"` в 36 файлах остаются. Они правильные, пока `app_language` верный.
5. Русский и немецкий тексты на ~30% длиннее английского. Возможна обрезка, это связано с болью 4.
6. Новые строки в `values/` без записи в `public.xml` — нормально: aapt2 сам выдаст id. Но строку с
   неэкранированным апострофом сборка не переварит, поэтому её отсеивает генератор.
7. Сервер продолжает писать свои ключи в общий MMKV с настройками (это уже есть и без нас). Полностью
   отключить загрузку можно позже, вместе с болью 10.

**Порядок работы:**
1. Генератор и валидатор `values-xx` (плейсхолдеры, `#`, экранирование, `krinik_overridden`).
2. Патчи 8а + 8б с пробным `values-ru` на 5 строк — проверить на Титане, что перехват работает.
3. Перевод 837 ключей (4724 слова) в `values-ru`.
4. 8д — библиотеки.
5. 8в — разметка.
6. 8г — код по белому списку.
7. Потом другие языки и решение, оставлять ли загрузку с сервера.

## 4. Какие языки знает приложение (только по константам в коде)

- **Список в настройках:** `zh, en, de, fr, it, es, ja, tu, pt, ru` — 10 языков
  (`SettingsNewActivity:366–375`). Турецкий записан кодом `tu`.
- **Автоопределение при первом запуске** (`FirstNewActivity.smali:520+`, sparse-switch): `de, es, fr, it, ja,
  pt` (и `pt-pt`→`pt`), `ru, tr, zh`, всё остальное → `en`. Значит, турок по системному языку получает
  `tr`, а в настройках тот же язык записан как `tu`: подпись языка не находится, и с сервера запрашиваются
  разные коды.
- `TribitApp.onConfigurationChanged` знает ещё `pl` и `pt-br` (`TribitApp.smali:703+`) и записывает их как есть.
- `api_lang` для кода удаления аккаунта принимает только `en_US`, `zh_CN`, `ja` (`ViewModelSettings:109`).
- Что сервер реально отдаёт по каждому коду, из кода не узнать, а запросов мы не делаем.
