## Вектор цели и приёмка

Класс, который переносим в `native/src/`, берётся из jadx уже без вызовов `foo$default(…)`: `javac` их не видит
(синтетические методы Kotlin), а руками переписывать сотни мест — работа машины (Achieve).

1. **Точность.** Ситуация: вызов `X.foo$default(a, b, dummy, mask, null)`. Действие: чистильщик. Результат: вызов
   `X.foo(a, b, <значение по умолчанию>)`, где на каждом месте с битом маски стоит значение по умолчанию функции, а не
   заглушка jadx. Проверка: `python -I tools/test_decompile_clean.py` — все примеры зелёные, среди них `launch` с маской 2
   (контекст задан, `start` по умолчанию) и с маской 3.
2. **Охват.** Scale: вызовы `$default` четырёх функций стандартной библиотеки (`replace`, `launch`, `split`, `contains`) в
   jadx-Java Tribit · Meter: `work/spike/default_calls.py` до и после · Target: 1 995 → 0.
3. **Эффект.** Scale: ошибки проверки типов замера · Meter: `work/spike/compile_spike.py` на очищенной копии · Target: 4 661
   → меньше на ≥ 1 500 (по замеру 2026-10-16 15:13 эти четыре функции дают 1 995 вызовов из 2 410).
4. **Честность.** Вызов функции вне таблицы чистильщик не трогает и печатает его в отчёт: ни одной догадки о значении по
   умолчанию.

## Риски

- Заглушка jadx совпадает со значением по умолчанию не всегда (`launch`: `null` на месте `EmptyCoroutineContext`) —
  поэтому подстановка по маске, никогда «отрезать хвост».
- Фасады Kotlin (`StringsKt__StringsJVMKt`) — внутренние части; вызов идёт через публичный фасад (`StringsKt`).
