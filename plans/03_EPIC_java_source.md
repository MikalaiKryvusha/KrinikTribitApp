## Вектор цели

**Боль.** Исправления пишутся в smali — ассемблере байт-кода: одна строка Java — 5–10 строк smali, читать и проверять их
трудно. Владелец хочет код на Java и Kotlin.

**Куда идём (Achieve).** Каждый класс Tribit, который мы чиним, становится исходником на Java или Kotlin в
`native/src/`: чистый код с комментариями, собирается вместе с приложением, его smali удалён. Со временем так переходит
весь код Tribit (2 006 файлов `com/thousandshores`).

**Почему класс за классом.** `FORK:` варианты «весь код сразу» | «класс за классом» · цена ошибки: недели на проект,
который не собирается · consulted: сопровождающие jadx — пересборка декомпиляции «only works for small and simple apps»
(skylot/jadx#947), «Edit java code is pointless because in most case it is not possible to recompile app» (#1959); модель
DexPatcher (класс на Java против символов исходного APK); наш замер — 4 661 ошибка проверки типов в 959 из 1 940 файлов
(`researches/10` §3).

## Критерии приёмки

1. **Класс на Java.** Ситуация: класс Tribit, который чиним, лежит в `native/src/` как `.java`, его `.smali` в `native/`
   нет. Действие: `bash build.sh debug`, установка на A51. Результат: экран этого класса работает, исправление видно.
   Проверка: `git -C native ls-files "*<Класс>.smali"` пусто; прогон в `testcases/reports/` со снимком.
2. **Класс на Kotlin.** То же для `.kt` (фаза 4).
3. **Счётчик переноса.** Scale: число классов `com/thousandshores` в виде исходника · Meter: скрипт счётчика (фаза 1) ·
   Target: растёт с каждым исправлением; 2 006 из 2 006 — конец эпика.
4. **Ничего не сломано.** После каждой фазы debug-сборка проходит на A51 главный → колонка → настройки → эквалайзер без
   вылетов (`logcat -b crash` — 0 строк приложения).

## Фазы

| # | Фаза | Что даёт | Ворота закрытия |
|---|---|---|---|
| 1 | **Гибридная сборка** | `native/src/` + шаг `build.sh`: Java Tribit-классов компилируется против classpath приложения, dex добавляется, smali этих классов удалён; первый класс — маленький слушатель кнопки диалога «Сбой подключения» (сейчас его тело правит патч 34); счётчик переноса | критерий 1 на этом классе; критерий 4 |
| 2 | **Механический чистильщик декомпиляции** | скрипт снимает целое семейство ошибок Kotlin (`launch$default`, `replace$default`, искажённые `…constructor-impl`; ≈ 1 650 из 4 661) — больше классов переносится почти без ручной работы | число ошибок замера `researches/10` §3 падает на ≥ 1 500; скрипт проверен на сломанном примере |
| 3 | **Наша Java в одном доме** | `patches/java/krinik/*` переезжает в `native/src/krinik/`; `patches/apply.py` остаётся только шагом варианта | сборка без `patches/java`; критерий 4 |
| 4 | **Kotlin** | `kotlinc` в сборке, `-api-version` по Kotlin внутри APK; первый класс на Kotlin | критерий 2 |
| 5 | **Перенос по ходу работы** | каждое новое исправление переносит свой класс в исходник | критерий 3 растёт; каждая сборка — критерий 4 |

Порядок: 1 → 2 → 3 → 4 → 5. Фаза 1 — фундамент: без неё класс на Java некуда положить. Фаза 2 удешевляет каждый перенос и
идёт до массовых переносов. Фаза 3 — чтобы наш код и код Tribit жили в одном месте. Фаза 4 — после того как Java-путь
работает (тот же путь, другой компилятор). Фаза 5 — постоянный режим.

## Риски

- **(а) Высокий:** класс в исходнике и его smali одновременно в APK — Android берёт первую копию
  (android.googlesource.com/platform/art/+/de7b436). Защита: шаг сборки падает, если для класса из `native/src/` есть smali.
- **(а) Высокий:** декомпилированный класс компилируется, но работает иначе (decompilers 78 % семантически верных классов,
  arxiv.org/abs/1908.06895). Защита: класс берётся в перенос только с прогоном его экрана на A51.
- **(б) Средний:** лимит 65 536 ссылок на dex (EXP-0010). Защита: наш dex отдельный, d8 делит его сам.
- **(в) Низкий:** jadx 1.5.1 уязвим при выгрузке Gradle (CVE-2026-42049) — обновить до запуска Gradle.
