2. **`checkpoint wire-hooks` has no per-hook opt-out.** After the owner-mandated unwire of `pretool-owner-word` and
   `stop-owner-answer`, the checkpoint refused: "the delivered hooks are NOT wired … run wire-hooks". The only legal
   path was `--verdict`, whose text is about a HARNESS refusal; the record now reads "wire-hooks NOT wired … owner's
   decision". Suggest a `"hooks": {"off": ["pretool-owner-word", "stop-owner-answer"]}` form in `.kaif/kaif.json` that
   `wire-hooks`, `check` and the checkpoint all honour — #144 makes this the field's common case.
3. **The project's own unanchored `.gitignore` line hides `.kaif/tools/` (class of #130).** The fork's pre-KAIF `tools/`
   line (meant for `apktool.jar` and `jadx/`) ignored 13 shipped modules under `.kaif/tools/`; `kaif-core check` caught it
   with a precise per-file hint. Fixed locally by anchoring (`/tools/apktool.jar`, `/tools/jadx/`). Suggest the installer
   runs that `check-ignore` scan at install time and prints it in the final summary — on a live project it is the
   first commit that would silently drop the modules.
4. **`kaif-voice-lint load` output size (#143 item 3 — avoided).** Load printed 64 141 bytes; redirected to a file and read
   whole instead of piping through `head -c`. A `--out <file>` flag is still worth adding.
