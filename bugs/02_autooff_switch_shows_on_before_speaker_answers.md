# Bug 02 — настройки колонки: «Автоматическое выключение» показано включённым, пока колонка не ответила

**Status:** 🔴 OPEN · **Severity:** S2 · **Fixing:** после патча 25, отдельным патчем (начальное состояние переключателей —
«неизвестно», пока колонка не прислала своё)
**Version/build:** Krinik Tribit debug, сборка 2026-10-16 12:28 +03:00 (патчи до 25) · **When/context:** прогон патча 25 на A51
с StormBox Blast 2, 2026-10-16 12:28–12:31 +03:00

## Symptom

В 12:29 экран настроек Blast 2 показал «Автоматическое выключение» включённым (жёлтый переключатель, снимки
`testcases/reports/shots/2026-10-16_patch8/37_settings.webp`, `39_autooff_check.webp`). Утром владелец просил держать
автовыключение колонки выключенным (`STATUS.md`). Колонка при этом, по журналу, оставалась выключенной (Forensics).

## Repro (deterministic — not yet)

Наблюдалось один раз из четырёх открытий настроек за 12:15–12:30. Гипотеза пути: открыть настройки колонки сразу после
перезапуска приложения, пока колонка ещё не прислала состояния → переключатель показывает значение по умолчанию.

## Forensics

- Код: `Bts56InfoActivity.isShutDown = true` по умолчанию (`decompiled/…/bts56/Bts56InfoActivity.java:162`); значение
  колонки ставится в строке 1190 и пишется в журнал «自动关机-- <значение>» (строка 1200); нажатие — строки 1995–2015
  (`autoCloseSet`, журнал «自动关机-- 设置 <значение>»).
- Журналы (`diagnostics/`, вне git): колонка ответила «自动关机-- false» в 12:15:32 и 12:24:35
  (`2026-10-16_patch25_run1.log`, `…_run2.log`); при открытии в 12:29 строки чтения нет; 12:29:59 — нажатие агента
  «自动关机-- 设置 false» (вернуть «выкл»); 12:30:46 — колонка снова «自动关机-- false» (`2026-10-16_autooff.log`).
- Команды «включить» (`设置 true`) нет ни в одном снятом журнале; промежуток 12:24:53–12:28:51 журнала не имеет
  (`logcat -c` перед установкой в 12:28).

## Root cause / Hypotheses

1. (основная) Экран показывает `isShutDown = true` по умолчанию, пока колонка не ответила; в 12:29 ответ не пришёл.
2. (проверить) Колонка в 12:29 не ответила на запрос состояний — почему (раньше отвечала за секунды).
3. (исключить) Что-то из патча 25 нажало переключатель: патч вешает слушатели только на `tv_version` и `ll_fire_version`;
   команды `设置 true` в журналах нет.

## Fix plan

Начальное состояние переключателей настроек — «неизвестно» (серый, не нажимается), пока колонка не прислала данные;
двойники — те же поля по умолчанию в остальных `*InfoActivity` (поиск `public boolean is[A-Z][a-zA-Z]* = true;`).

## Decisions made without the owner

- 12:29:59 агент нажал переключатель, чтобы вернуть «выкл» (состояние, о котором просил владелец утром); колонка
  подтвердила «false» в 12:30:46.
