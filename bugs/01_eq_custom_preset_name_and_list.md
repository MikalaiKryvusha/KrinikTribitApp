# Bug 01 — свой пресет эквалайзера: имя будто не сохраняется, пресета нет в списке до перезапуска

**Status:** 🔴 OPEN · **Severity:** S2 · **Fixing:** после разбора кода `Eq56DetailActivity.saveEq` и списка `Eq56SettingActivity`
**Version/build:** Tribit 5.0.0 (оригинал) и Krinik Tribit debug (патчи 1–7, 11, 16–18) · **When/context:** слова владельца в чате
2026-10-16 ≈ 01:16 +03:00, во время прогона на Титане

## Symptom

Слова владельца дословно (чат 2026-10-16 ≈ 01:16 +03:00): «ещё имя было не сохранить... словно не применяло сохранение» ·
«хотя по факту профиль сохранился» · «но в списке его не было» · «потом после перезапуска словно появился» · «короче - полно
багов приложение».

## Repro attempts (Krinik Tribit debug, StormBox Blast 2, Титан)

1. 01:14 — «На заказ» → «New Custom» → назад без кнопки сохранения: пресет **сохранился сам** под именем «Безымянный
   эквалайзер1» и стал текущим на странице колонки. Кнопки сохранения в редакторе нет — сохранение происходит при выходе.
2. 01:19 — «New Custom» при уже сохранённом безымянном пресете: редактор открылся, вылета нет (патч 1).
3. 01:24 — имя заменено на «Krinik test» → назад, назад: в списке «На заказ» сразу «Krinik test»; «Безымянный эквалайзер1»
   из списка пропал. После перезапуска приложения — то же: один «Krinik test».

Сценарий владельца (имя не применилось, пресета нет в списке до перезапуска) в попытке 3 **не воспроизведён**; найдено
соседнее: второй свой пресет вытеснил первый. Нужны ещё варианты: переименование существующего пресета; сохранение через
выход жестом «назад» и кнопкой; два пресета подряд; оригинальное приложение.

## Forensics

Снимки: `testcases/reports/shots/2026-10-16_ours/23_new_custom.webp` … `34_after_restart.webp`. Поле имени показывает
«Безымянный эква» — имя обрезано до 15 символов (ограничение длины поля), полное имя в списке — «Безымянный эквалайзер1».

## Root cause / Hypotheses

1. Сохранение идёт асинхронно в колонку и в локальную базу; список читает базу до конца записи — отсюда «нет в списке до
   перезапуска».
2. У StormBox Blast 2 одна ячейка под свой пресет — новый пресет перезаписывает старый (тогда это поведение колонки, и
   приложение должно об этом говорить).

## Fix plan

Прочитать `Eq56DetailActivity.saveEq` / `postEqData` и наблюдатель списка в `Eq56SettingActivity`; воспроизвести на
оригинале; патч по итогам.
